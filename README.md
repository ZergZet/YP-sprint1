# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**
- Пользователи могут удалённо включать/выключать отопление в своих домах
- Система поддерживает управление выключателями отопления в домах

**Мониторинг температуры:**
- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс
- Система поддерживает получание данных о температуре с датчиков, установленных в домах

**Подключение домов:**
- Инженеры могут регистрировать/подключать датчики в новых домах
- Система поддерживает регистрацию датчика и дома при подключении

### **4. Проблемы монолитного решения**
Для поддержания текущих функциональных возможностей уже обслуживаемых клиентов:<br> 
- подключение домов<br>
  монолитность не является проблемой, неудобство связано с отсутсвием разработанного пользовательского интерфейса подключения и универсального интерфейса датчиков<br>
- производительность и масштабируемость<br>
  текущая нагрузка в сотни клиентов не требует усилий по разработке механимов масштабирования<br>
- обновление и непрерывность работы<br>
  работа отопления не зависит от работы приложения, поэтому время недоступности на период обновления для отопления не является проблемой<br>
  
Для ожидаемых функциональных возможностей:<br>
 - подключение домов<br>
	монолитность **не является проблемой**, разработка пользовательского интерфейса подключения решит проблему<br>
- подключение новых датчиков<br>
	монолитность **не является проблемой**, разработка универсального интерфейса коннекторов для подключения датчиков позволит успешно решить задачу и в монолите<br>
- производительность и масштабируемость<br>
	монолитность **не является проблемой**, подключение нескольких посёлков учитывая малый размер команды дешевле решить вертикальным масштабированием, либо распределением домов по нескольким серверам, если число обслуживаемых объектов перевалит за 1000, что выгоднее настройки и обслуживания кластера на микросервисной архитектуре дорогостоящими специалистами.<br>
	Но при дальнейшей перспективе масштабирования с необходимостью увеличения числа серверов и распределения по ним домов уже будет **являться проблемой** для администрирования и обслуживания всей инфраструктуры.<br>
- обновление и непрерывность работы <br>
  планируемые интерактивные функции:<br>
  - запирать и отпирать автоматические ворота,
  - удалённо наблюдать за домом,
  - возможно и будущее неуточнённое поведение умного дома<br><br>
резко повышают потребности в непрерывности работы и отказоустойчивости решения,
	- переключение управления на другой узел можно обеспечить и в монолитной архитектуре, но требования поддержки со стороны высоко квалифицированных специалистов существенно вырастут, что **является проблемой**.<br>
	- обеспечение совместимости версий монолита для обеспечения непрерывной работы при обновлениях уже **является проблемой**. <br>

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры

Ревьюер будет проверять точно так же.
